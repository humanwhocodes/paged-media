# Agent instructions

## Project overview

This repository is a Node.js library that polyfills CSS Paged Media features in browsers and helps produce paginated documents and PDFs. It uses ES modules and requires Node.js 22 or newer.

## Repository layout

- `src/` contains the TypeScript library implementation and unit tests (`*.spec.ts`).
- `tests/` contains Vitest integration tests (`*.test.ts`), Puppeteer helpers, HTML/CSS fixtures, and platform-specific screenshot baselines.
- `scripts/` contains the browser bundle builder, native-support probe, and PDF renderer.
- `docs/` contains feature support, requirements, and comparison documentation.
- `dist/` is generated by the build; do not edit generated output directly.

## Setup and validation

Install dependencies with `npm ci`. Common commands:

- `npm test` runs the full Vitest suite; its `pretest` hook builds the browser bundle first. Integration tests use Puppeteer and fixtures under `tests/fixtures/`.
- `npx vitest run <filename>` runs a focused test file.
- `npm run lint` runs ESLint and the TypeScript check (`tsc -p tsconfig.check.json`).
- `npm run build` runs the TypeScript build and generates the browser bundle.
- `npm run test:firefox` runs the suite in Firefox (install the browser first with `npx puppeteer browsers install firefox`).
- `npm run test:screenshots` runs visual regression tests. Update screenshot baselines only for intentional rendering changes, using `npm run test:screenshots:update`.

When changing pagination or rendering behavior, add or update focused tests and relevant fixtures. Preserve cross-platform rendering expectations; screenshot baselines are platform- and browser-specific.

## Code conventions

- Follow [`.github/instructions/javascript.instructions.md`](.github/instructions/javascript.instructions.md) for JavaScript and TypeScript style (tabs, double-quoted strings, and braced conditionals).
- Validate inputs at public method entry points. Use `TypeError` for invalid argument types and `Error` for business-logic failures; keep error messages specific and test their exact text.
- Add tests for success and error paths, and cover async or concurrent behavior when relevant. Mock external dependencies where appropriate.
- Keep changes focused and avoid editing generated files in `dist/`.

## Commit messages and pull requests

Commit messages and pull request titles **must** use Conventional Commits format: `type(scope): description` (the scope is optional). Choose a type and optional scope that accurately describe the change, for example `fix(layout): preserve page breaks` or `docs: clarify test setup`. Keep the description concise and use the same format for every commit and PR title.
